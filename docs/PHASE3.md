# 第三期 · 新功能实施计划

分支：`feat/phase3`（基于 `fix/stability`，最后与稳定性修复一起合并进 main）。
规则：一步一个提交；每步做完跑 `cargo test --release` + `cargo clippy --release --all-targets -- -D warnings`，
本机重启宠物实测，然后在本文件勾选并写一行结果，再开始下一步。不提交 config.json / 日志 / 任何 Key。

## 第 0 步 · 本机事件接口（地基）✅
- [x] 传输改用 WM_COPYDATA 发给同一桌面上的宠物窗口（比命名管道省事：不开端口，天然只收同会话同桌面、完整性不低于宠物的进程）；魔数 "HKE1"，载荷 ≤4 KB 的一行 JSON
- [x] `hakimi-pet.exe --event done|error|wait|info [--source 名字] [--msg "一句话"]`：交给正在跑的那只后退出（退出码 0）；没在跑或参数错 → 退出码 1，不起第二只；没加引号被拆开的值会自动拼回去
- [x] `AppEvent::External(ExtEvent)` → behavior/external.rs：done 星星眼、error 发抖、wait 问号、info 只冒气泡；msg 只显示不念（最多显示 60 字）
- [x] 限流：同源同类 3 秒内只算一次；msg 截 200 字、去控制字符；她忙（聊天/拎着/跳舞/提醒在响）时先攒着，同源只留最新，最多 4 条，10 分钟过期
- 验收：命令行发 done / error / wait / 再 done / 错误参数，日志依次记到 4 个事件，错误参数退出码 1 ✅

## 第 1 步 · 跟着我的歌跳（跟实时节拍）
- [x] 现状：菜单「跟着我的歌跳」（songs 文件夹，事先分析整首）保留；新增「🎧 跟着正在放的歌跳」
- [x] 只读默认输出设备的峰值电平表（IAudioMeterInformation，不录音、不抓音频数据），约 15 ms 一次，留最近 8 秒，每 1.5 秒按 20 ms 一格估一次节拍（复用 beat::analyze），锁相环平滑跟上，换歌/变速会跟着变
- [x] 开跳 4.5 秒还没声音 → 「没听到在放歌」收场；听到过之后安静 5 秒 → 正常收场；最长 10 分钟；开场白只出气泡不念（念出来会混进电平）
- [x] 不内置任何音源
- 验收：放两首不同速度的歌，舞步快慢跟着变（单测：120 BPM 抖动采样估出 ±3 BPM 内；实机待主人放歌试）
